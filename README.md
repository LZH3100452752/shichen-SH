# 时尘 · 自动救砖守护 AutoRescue

> 一个运行在 Android Root 环境下的 Bootloop 防护与自动救砖模块。
> 当模块冲突、脚本错误、误删系统文件等原因导致手机反复重启、无法进入桌面时，
> 它会在下一次开机自动介入，逐步禁用可疑模块，把手机"救"回桌面。

支持 **Magisk / KernelSU / APatch**，自带可视化 WebUI 管理界面。

## 一、它解决什么问题

玩模块的人几乎都遇到过这类场景：

- 装了个新模块，重启后卡在开机动画，进不去桌面
- 两个模块改了同一个系统文件，冲突导致无限重启
- 模块脚本里有死循环或危险命令，开机阶段直接把系统拖死
- 不知道该禁哪个模块，只能在 Recovery 里盲删

**AutoRescue 的思路**：既然绝大多数变砖都是"模块导致的"，那就让系统在启动失败时
自动、渐进地把模块一个个排除掉，直到能进桌面为止。整个过程不需要你操作，
也不需要电脑和数据线。

## 二、核心机制

### 1. 启动计数

每次开机计数 +1；成功进入桌面并稳定运行一段时间后清零。
若连续失败达到阈值（默认 3 次），判定为 Bootloop，触发救援。

### 2. 三级渐进救援

不是一刀切全禁，而是**逐级加重**，救活为止：

| 等级 | 行为 |
|---|---|
| **L1** | 禁用全部非白名单模块 |
| **L2** | 连同白名单一起禁用，仅保留守护自身 |
| **L3** | 重命名模块目录，彻底移除挂载 |

若某一级救不回来，下次开机会自动加重到下一级。
到达设定的最大等级仍失败时会**熔断停止**，避免变成无限重启循环耗光电量。

### 3. 白名单与锁定

- **白名单**：加入的模块在 L1 中不会被禁用
- **锁定（排除名单）**：更强，任何救援等级都不会动它
- 守护自身模块**永久受保护**

### 4. 多种触发条件

除了启动计数，还覆盖这些场景：

- 开机超时未宣告 `boot_completed`
- 卡在 `post-fs-data` 阶段（脚本死循环的典型症状）
- 卡在 `service` 阶段
- `system_server` 短时间内崩溃多次
- Zygote 反复重启
- 手动标记"下次启动强制救援"

### 5. 快照与回滚

- 救援前自动保存当前模块启用状态快照
- 每次稳定开机自动记录"黄金配置"
- 随时可一键回滚到任意快照或黄金配置

## 三、功能清单

### 救砖与恢复

- 三级渐进自动救援
- 救援演练：**推演**每个等级会禁用哪些模块，全程不改任何东西
- 一键安全模式：移除全部模块挂载
- 阶段精准救援：卡在 `post-fs-data` 就只禁带该阶段脚本的模块，其他模块不动
- 修复模块文件权限：权限错误会导致脚本不执行，症状很像变砖
- 修复 SELinux 标签：解决 `unlabeled` 导致系统拒绝执行
- 清理损坏模块目录：删除没有 `module.prop` 的残留与空壳模块
- 手动救援脚本：Recovery 里执行 `sh /data/adb/modules/auto_rescue/tools/rescue.sh`，菜单式操作
- 在 `/data/local/tmp` 生成救援说明，便于 Recovery 手动处理

### 脚本安全检测

- 危险代码识别，分四级（critical / high / medium / low）
  - 整机格式化删除、递归删 `/system` `/data` `/vendor`
  - 清空模块目录、`dd` 写块设备、`mkfs` 格式化、向分区写零
  - Fork 炸弹、循环重启、杀 Zygote、关闭 SELinux 等
- 加密脚本识别与基础解密：
  - base64（含 url-safe 变体、分片拼接）、gzip、xz、bzip2、lzma
  - hex、ROT13 / 凯撒（全 25 种位移暴力）、字符倒序
  - **支持多层嵌套拆解**，解出后再对明文复检
- Shell 规范化：还原变量拼接、引号切割、`${IFS}` 绕过等混淆手法
- 三种入口：按模块 / 按路径 / 粘贴代码，也支持全部模块一键体检

### 系统防护

- 重要目录守护：建立基线 → 定期巡检 → 目录消失或条目骤降立即记录告警
- 危险进程扫描：检测正在执行危险删除命令的进程
- 系统健康检查：关键系统文件缺失、存储空间告急、损坏模块、SELinux 状态、
  覆盖 `/system` 的模块数量统计
- 只读加固与防护配置备份

### 冲突检测

- 扫描哪些模块在覆盖同一个系统文件
- 覆盖 `/system` 的模块越多，冲突开不了机的概率越大

### 模块管理

- 启用 / 禁用 / 白名单 / 锁定
- 模块备份与还原（整目录复制）
- 模块内脚本体检
- 模块文件查看

### 云更新

- 打开界面自动静默检测一次，有新版才弹窗
- 手动检测、更新源连通性测试
- 支持**强制更新**版本（不更新无法关闭弹窗），由云端 `force` 字段控制
- 下载 / 安装分两段进度显示
- 安装前自动保存快照，装完提示重启，有问题可回滚
- 内置多个源，自动取版本号最大的那份，规避 CDN 缓存导致的版本回退

### 界面

- 10 种语言：简体中文、繁體中文、English、日本語、한국어、
  Русский、Français、Español、Deutsch、Tiếng Việt
- 深色科技风 + 金属蓝银配色，含品牌 LOGO 启动页
- 分步加载遮罩、进度环、骨架屏、扫描线动效
- 7 个主页面：总览 / 救援 / 模块 / 检测 / 防护 / 设置 / 工具
- 设置改动自动保存，无需手动点保存
- 诊断包导出、日志查看、root 命令终端

## 四、安装

1. 确保设备已 Root，并装有 Magisk / KernelSU / APatch
2. 下载 `AutoRescue_xxx_by_shichen.zip`
3. 在面具 App 中「模块 → 从本地安装」选择该 zip
4. 重启

安装过程会显示实时进度条，结束后建议重启一次使守护完全生效。

---

## 五、使用

### 打开界面

- **KernelSU / APatch / MMRL**：支持内嵌渲染，直接打开
- **其他**：点模块卡片上的「执行 / Action」按钮，会自动拉起本地服务并用浏览器打开
- 命令行：`sh /data/adb/modules/auto_rescue/common/api.sh status`

### 已经进不去桌面时

1. 进入 Recovery
2. 执行：`sh /data/adb/modules/auto_rescue/tools/rescue.sh`
3. 按菜单选择救援方式

多数情况下模块会在开机阶段自动完成救援，不需要手动操作。

### 更换 LOGO（可选）

把正方形图片命名为 `logo.png`，放到
`/data/adb/modules/auto_rescue/webroot/assets/img/` 下即可，无需改代码。
